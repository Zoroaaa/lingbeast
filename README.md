# 灵兽录 · 山海新契

像素风回合制灵兽收集 RPG。玩家以青溪末门弟子的身份入山，在十九境中探索、结契、解碑、问名，最终面对「新契」或「断契」的抉择。

前端为 Phaser 3.90 + 原生脚本（无构建工具、可离线运行），后端为 Cloudflare Worker + D1，静态资源与 `/api/*` 同源部署。

> 版本 2.4.1 · 存档 v4 · 十九境 · 62 种灵兽 · 12 章主线 · 63 条支线

## 世界观

三十年前，十二山门为争灵脉铸出锁灵器，强抽灵兽灵息，酿成「断契之乱」。灵脉逆流，渊兽自裂谷爬出，山门一夜覆灭。如今只剩青溪末门还点着灯。

玩家从青溪山门出发，沿灵脉遗迹逐境深入：修桥、采药、铸灵、问价、破幻、解契，最终在归墟深处击败无相，决定是重立新契，还是斩断锁链。

## 核心玩法

### 探索

- 八张手工绘制的大地图，尺寸 44×34 至 86×62，地貌、天气与色调各不相同
- 点击地面自动寻路，NPC、灵兽、宝箱、采集点、碑文、暗格均可点击交互
- 键盘 WASD / 方向键行走，移动端提供虚拟摇杆与交互键
- 小地图、区域入场标题、场景 HUD、任务追踪与队伍缩影
- 天时（晨 / 昼 / 暮 / 夜）与天气（晴 / 雨 / 雾 / 烬雨）会改变五行威力与稀有灵兽出现率
- 采集点按章节或天气刷新，宝箱与暗格含灵玉、道具、灵器与剧情标记

### 战斗

- 回合制战斗，按速度排序行动；队伍最多 3 只灵兽，可中途换人
- 五行相克：木克土、土克水、水克火、火克金、金克木
- 六种状态：灼烧、腐蚀、迟滞、破甲、护盾、蓄势
- 术法、结契、丹药、遁走四项指令；削弱目标后以灵符提高结契成功率
- 契势槽：命中与受击累积契势，满 100 后可发动「合契」，两名灵兽联手追击并回复气血
- 13 场 Boss 战，4 种 AI 原型（强攻 / 守御 / 回复 / 诡诈），60% 与 30% 血量触发阶段提示，Boss 不可结契
- 战后结算经验、灵玉、掉落与图鉴记录，支持战斗演出、浮动伤害数字与自动战斗
- 战斗速度 1x / 2x / 跳过；跳过时直接结算，不再播放命中与漂浮演出
- 自动战斗：自动选克制术法、低血服丹、力竭自动换灵；可设定结契阈值自动捕捉野生灵兽
- 六步新手引导：入谷、遭遇、削弱、结契、查看队伍、过第一章；可跳过，也可在设置中重看

### 养成

- 62 种灵兽形态，野外结契与进化形态并存；等级上限 40
- 灵兽拥有资质、契势、4 个随等级解锁的技能与可装备灵器
- 灵兽栏可升级至 5 级，提升容量与结契成功率
- 12 种灵诀（被动）：先发、灵犀、坚甲、回灵、烈火、润泽、破甲、契心、云行、炉心、沉息、根守
- 28 件灵器，分契印 / 护符 / 灵铃 3 个槽位、4 档品阶（旧 / 良 / 珍 / 绝）与 6 套套装效果
- 灵器只通过探索、Boss 首杀与剧情抉择获得，可在行囊中装备、卸下与出售

### 剧情、任务与抉择

- 12 章主线，从「谷口问灵」到「山海同流」
- 63 条支线（含多阶段推进）、3 类山门悬赏（讨伐 / 采办 / 巡山）
- 12 处剧情抉择，选项会改变契心 / 锁心立场、6 方声望、灵玉、道具、灵诀、配方与后续对话
- 90 条山海志、78 处碑文、6 处暗格，碑文与图鉴进度共同解锁世界观条目
- 两种结局「新契」与「断契」，通关后可继续游历、补完图鉴并挑战山海试炼
- 8 层山海试炼，每层有独立规则与强化 Boss

### 经济与制作

- 灵玉为主要货币，来源包括战斗、宝箱、任务、悬赏与灵器出售
- 5 家商店（山门货铺、归墟行商、云市货摊、沉市货铺、暗市摊位），商品按章节解锁
- 14 种材料、16 种道具、16 张配方；配方可通过初始、支线、碑文或山海志解锁
- 丹药、灵符、清心散、归元丹、引灵香、遁地符、灵笼升级均可制作或购买

## UI 与可访问性

- 统一设计 token：颜色、间距、字号、焦点环与动效参数集中在 `public/style.css` 顶部；新增界面优先复用 `.panel`、`.btn`、`.badge`、`.bar` 等基础件，不再引入新的 UI 框架或外部字体
- 像素羊皮纸视觉：自有按钮、册页、对话框、战斗 HUD 与移动端 HUD 样式；NES.css 已移除，`public/vendor/` 只保留 Phaser
- 键盘与读屏：模态使用 `role="dialog"` + `aria-modal` + 背景 `inert`，打开时锁定焦点、关闭时回到触发按钮；页签支持左右方向键与 Home / End；战斗指令、战果页、提示消息均带可读标签
- 显示偏好：设置中提供标准 / 大字号、减少动效、震屏与触摸控件开关；大字号只放大界面文字，不放大场景画布
- 移动端：窄屏 HUD 收为三列菜单与顶部状态条，适配安全区；触屏提供左侧摇杆与右侧「契」键，菜单展开时不会被引导卡遮挡
- 性能：山河图换选只更新选中节点与详情面板，不重建整张 SVG；小地图在不可见时跳过重绘

## 技术栈

- Phaser 3.90（`public/vendor/phaser.min.js`，离线内置）
- 原生 JavaScript，经典 `<script>` 顺序加载，无打包、无框架、无构建步骤
- WebAudio 程序化音效与环境乐，无外部音频文件
- 自有设计 token + 像素羊皮纸样式（`public/style.css`，规范见 `docs/ui-guidelines.md`）
- Cloudflare Workers：静态资源（`ASSETS` 绑定）+ API
- Cloudflare D1：账号、会话与云存档
- PWA：manifest + Service Worker，可安装、可离线续玩本地进度
- Wrangler 4

## 存档与云同步

- 本地存档键为 `lingbeast.save.v4`，优先写入 `localStorage`，离线可完整游玩
- 启动时自动迁移 v1 / v2 / v3 旧存档，并保留 v3 备份
- 登录后每 2 秒防抖推送云存档；失败保留任务并每 6 秒重试
- 服务端按 `updated_at` 处理写入冲突，并把客户端时间钳制在服务器当前时间以内
- 冲突时弹出「本机 / 云端」双版本对比（章节、区域、队伍、灵玉、落笔时间），由玩家选择采用云端或保留本机覆盖
- 战斗或对话中收到冲突会暂存，回到世界后再提示，不会打断当前结算
- 会话有效期 30 天，密码使用 PBKDF2-SHA256（10 万次迭代、随机盐）存储
- 单次存档上限 100 KB；未登录或接口异常时自动降级为纯本地模式

## 本地开发

```bash
npm install
npm run db:init:local   # 初始化本地 D1
npm run dev             # http://localhost:8787
```

仅调试前端时，也可用任意静态服务器指向 `public/`（云存档接口不可用，本地存档正常）：

```bash
npx serve public
```

工程脚本：

```bash
npm run check          # 资源引用、PWA 图标、UI 静态检查与灵兽立绘自检
npm run ui:check       # 只跑 UI：对比度、ARIA、重复 id、脚本语法
npm run art:check      # 灵兽立绘：rect 预算、bbox、家族区分度、进化链
npm run art:preview    # 生成 62 只灵兽立绘总览（.tmp/art-preview.html）
npm run version:bump   # 所有 ?v= 与 sw.js VERSION 一起 +1
npm run icons          # 重新生成 PWA 图标
```

灵兽立绘的分层、家族表、验收标准与「为什么保留部件拼贴引擎」见 [`docs/beast-art.md`](docs/beast-art.md)。

新增或修改 `public/` 下的资源后，运行 `npm run version:bump`，不要手工逐行改 `?v=`。

## 部署

首次部署前确认 `wrangler.jsonc` 中的 `database_id` 为真实 D1 ID：

```bash
npx wrangler d1 create lingbeast   # 若尚未创建，将返回的 ID 填入 wrangler.jsonc
npm run db:init:remote             # 初始化远程表结构
```

手动部署：

```bash
npm run deploy
```

### GitHub 推送自动部署（Workers Builds，零密钥）

1. Cloudflare Dashboard → Workers & Pages → 选择 `lingbeast-rpg` → Settings → Builds → Connect
2. 连接 GitHub 仓库，生产分支选 `main`
3. Build command 填 `npm ci`，Deploy command 保持 `npx wrangler deploy`
4. Worker 名称必须与 `wrangler.jsonc` 中的 `name`（`lingbeast-rpg`）一致

无需配置 API Token，Cloudflare 自动生成构建凭据。若部署报 D1 权限错误，可在构建设置中改用带 `D1:Edit` 权限的自建 Token。

## PWA 与离线

- `manifest.webmanifest` 提供安装信息与 192 / 512 / maskable 图标
- `sw.js` 对导航请求网络优先、对静态资源缓存优先，并按版本号清理旧缓存
- 本地 `localhost` / `127.0.0.1` 不注册 Service Worker，避免缓存掩盖开发改动
- 离线时本地存档与已缓存的场景可继续游玩；云存档相关接口自动降级

## API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/health` | 健康检查，不参与限流 |
| POST | `/api/register` | 注册并登录（PBKDF2 加盐哈希），道号 3–20 位 |
| POST | `/api/login` | 登录并签发 30 天会话令牌 |
| POST | `/api/logout` | 注销当前 Bearer 令牌 |
| GET | `/api/save` | 拉取云存档（未登录返回 401） |
| PUT | `/api/save` | 写入云存档，按 `updatedAt` 去重并返回冲突存档 |

除健康检查外，同一 IP 每分钟超过 12 次请求返回 429；鉴权使用 `Authorization: Bearer <token>`；存档写入上限 100 KB。`PUT /api/save` 会校验 payload 为 JSON 对象，并把客户端 `updatedAt` 钳制到服务器当前时间，防止未来时间锁死账号。

## 内容校验

`js/data/validate.js` 在启动时执行 `validateContent()`，检查：

- 区域出生点、出口、Boss、碑文、NPC、宝箱、采集点是否越界或不可达
- 区域、Boss、灵兽、技能、状态、材料、配方、商店、任务、抉择之间的引用完整性
- 每境内容规格、Boss 不可结契与阶段提示、灵兽 4 技能、试炼 8 层等硬性约束

`npm run check` 另行检查 `index.html` 的本地资源是否存在、`?v=` 是否统一、`sw.js` 版本是否同步、manifest 图标是否齐全。

当前校验结果为 0 错误。新增或修改区域内容后，应先跑 `npm run check`，再做浏览器实测，最后 `npm run version:bump`。
