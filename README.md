# 灵兽录 · 山海新契

像素风回合制灵兽收集 RPG。玩家以青溪末门弟子的身份入山，在八境中探索、结契、解碑、问名，最终面对「新契」或「断契」的抉择。

前端为 Phaser 3.90 + 原生脚本（无构建工具、可离线运行），后端为 Cloudflare Worker + D1，静态资源与 `/api/*` 同源部署。

> 版本 2.1.0 · 存档 v4 · 八境 · 16 种灵兽 · 8 章主线 · 39 条支线

## 世界观

三十年前，十二山门为争灵脉铸出锁灵器，强抽灵兽灵息，酿成「断契之乱」。灵脉逆流，渊兽自裂谷爬出，山门一夜覆灭。如今只剩青溪末门还点着灯。

玩家从青溪山门出发，沿灵脉遗迹逐境深入：修桥、采药、铸灵、问价、破幻、解契，最终在归墟深处击败无相，决定是重立新契，还是斩断锁链。

## 核心玩法

### 探索

- 八张手工绘制的大地图，尺寸 44×34 至 86×62，地貌、天气与色调各不相同
- 点击地面自动寻路，NPC、灵兽、宝箱、采集点、碑文、暗格均可点击交互
- 键盘 WASD / 方向键行走，移动端提供虚拟摇杆与交互键
- 小地图、区域入场标题、场景 HUD、任务追踪与队伍缩影
- 天时（晨 / 昼 / 暮 / 夜）与天气（晴 / 雨 / 雾 / 烬雨）会改变五行威力与稀有灵兽出现率
- 采集点按章节或天气刷新，宝箱与暗格含灵玉、道具、灵器与剧情标记

### 战斗

- 回合制战斗，按速度排序行动；队伍最多 3 只灵兽，可中途换人
- 五行相克：木克土、土克水、水克火、火克金、金克木
- 六种状态：灼烧、腐蚀、迟滞、破甲、护盾、蓄势
- 术法、结契、丹药、遁走四项指令；削弱目标后以灵符提高结契成功率
- 契势槽：命中与受击累积契势，满 100 后可发动「合契」，两名灵兽联手追击并回复气血
- 7 场 Boss 战，4 种 AI 原型（强攻 / 守御 / 回复 / 诡诈），60% 与 30% 血量触发阶段提示，Boss 不可结契
- 战后结算经验、灵玉、掉落与图鉴记录，支持自动战斗演出与浮动伤害数字

### 养成

- 16 种灵兽形态：11 种可野外结契，5 种为进化形态；等级上限 40
- 灵兽拥有资质、契势、4 个随等级解锁的技能与可装备灵器
- 灵兽栏可升级至 5 级，提升容量与结契成功率
- 8 种灵诀（被动）：先发、灵犀、坚甲、回灵、烈火、润泽、破甲、契心
- 19 件灵器，分契印 / 护符 / 灵铃 3 个槽位、4 档品阶（旧 / 良 / 珍 / 绝）与 3 套套装效果
- 灵器只通过探索、Boss 首杀与剧情抉择获得，可在行囊中装备、卸下与出售

### 剧情、任务与抉择

- 8 章主线，从「谷口问灵」到「山门重开」
- 39 条支线（含多阶段推进）、3 类山门悬赏（讨伐 / 采办 / 巡山）
- 8 处剧情抉择，选项会改变契心 / 锁心立场、6 方声望、灵玉、道具、灵诀、配方与后续对话
- 36 条山海志、36 处碑文、15 处暗格，碑文与图鉴进度共同解锁世界观条目
- 两种结局「新契」与「断契」，通关后可继续游历、补完图鉴并挑战山海试炼
- 5 层山海试炼，每层有独立规则与强化 Boss

### 经济与制作

- 灵玉为主要货币，来源包括战斗、宝箱、任务、悬赏与灵器出售
- 2 家商店（山门货铺、归墟行商），商品按章节解锁
- 7 种材料、8 种道具、8 张配方；配方可通过初始、支线、碑文或山海志解锁
- 丹药、灵符、清心散、归元丹、引灵香、遁地符、灵笼升级均可制作或购买

## 技术栈

- Phaser 3.90（`public/vendor/phaser.min.js`，离线内置）
- 原生 JavaScript，经典 `<script>` 顺序加载，无打包、无框架、无构建步骤
- NES.css + 自定义像素样式（`public/style.css`）
- Cloudflare Workers：静态资源（`ASSETS` 绑定）+ API
- Cloudflare D1：账号、会话与云存档
- Wrangler 4

## 存档与云同步

- 本地存档键为 `lingbeast.save.v4`，优先写入 `localStorage`，离线可完整游玩
- 启动时自动迁移 v1 / v2 / v3 旧存档，并保留 v3 备份
- 登录后每 2 秒防抖推送云存档；失败保留任务并每 6 秒重试
- 服务端按 `updated_at` 处理写入冲突，客户端以云存档为准并提示
- 会话有效期 30 天，密码使用 PBKDF2-SHA256（10 万次迭代、随机盐）存储
- 单次存档上限 100 KB；未登录或接口异常时自动降级为纯本地模式

## 本地开发

```bash
npm install
npm run db:init:local   # 初始化本地 D1
npm run dev             # http://localhost:8787
```

仅调试前端时，也可用任意静态服务器指向 `public/`（云存档接口不可用，本地存档正常）：

```bash
npx serve public
```

## 部署

首次部署前确认 `wrangler.jsonc` 中的 `database_id` 为真实 D1 ID：

```bash
npx wrangler d1 create lingbeast   # 若尚未创建，将返回的 ID 填入 wrangler.jsonc
npm run db:init:remote             # 初始化远程表结构
```

手动部署：

```bash
npm run deploy
```

### GitHub 推送自动部署（Workers Builds，零密钥）

1. Cloudflare Dashboard → Workers & Pages → 选择 `lingbeast-rpg` → Settings → Builds → Connect
2. 连接 GitHub 仓库，生产分支选 `main`
3. Build command 填 `npm ci`，Deploy command 保持 `npx wrangler deploy`
4. Worker 名称必须与 `wrangler.jsonc` 中的 `name`（`lingbeast-rpg`）一致

无需配置 API Token，Cloudflare 自动生成构建凭据。若部署报 D1 权限错误，可在构建设置中改用带 `D1:Edit` 权限的自建 Token。

## API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/health` | 健康检查，不参与限流 |
| POST | `/api/register` | 注册并登录（PBKDF2 加盐哈希），道号 3–20 位 |
| POST | `/api/login` | 登录并签发 30 天会话令牌 |
| POST | `/api/logout` | 注销当前 Bearer 令牌 |
| GET | `/api/save` | 拉取云存档（未登录返回 401） |
| PUT | `/api/save` | 写入云存档，按 `updatedAt` 去重并返回冲突存档 |

除健康检查外，同一 IP 每分钟超过 12 次请求返回 429；鉴权使用 `Authorization: Bearer <token>`；存档写入上限 100 KB。

## 内容校验

`js/data/validate.js` 在启动时执行 `validateContent()`，检查：

- 区域出生点、出口、Boss、碑文、NPC、宝箱、采集点是否越界或不可达
- 区域、Boss、灵兽、技能、状态、材料、配方、商店、任务、抉择之间的引用完整性
- 八境数量、每境内容规格、Boss 不可结契与阶段提示、灵兽技能数量等硬性约束

当前校验结果为 0 错误。新增或修改区域内容后，应先保证校验通过，再做浏览器实测并统一提升资源版本号（`index.html` 中的 `?v=`）。
